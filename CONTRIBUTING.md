# Contributing

Thank you for considering a contribution! Contributions are welcome in the form of bug reports, feature suggestions, documentation improvements, and code.

## Before You Start

This project is licensed under the [Elastic License 2.0](./LICENSE.md). Please read it before contributing.

## Contributor License Agreement (CLA)

All contributors must agree to the [Contributor License Agreement](./CLA.md) before their contribution can be accepted.

**By opening a pull request, you confirm that you have read and agree to the CLA.** No separate signature is required — your PR submission acts as your acceptance.

If you are contributing on behalf of your employer, you additionally confirm that your employer has authorised this assignment.

## How to Contribute

### Reporting bugs

Open an issue and include:
- A clear description of the problem
- Steps to reproduce
- Expected vs actual behaviour
- Your environment (OS, version, etc.)

### Suggesting features

Open an issue describing:
- The problem you are trying to solve
- Your proposed solution
- Any alternatives you have considered

### Submitting code

1. Fork the repository and create a branch from `main`.
2. Make your changes, keeping commits focused and descriptive.
3. Ensure existing tests pass, and add tests for new behaviour where applicable.
4. Open a pull request with a clear description of what you changed and why.

## Code Style

- Follow the conventions already present in the codebase.
- Keep changes minimal and scoped — avoid unrelated refactors in the same PR.

## What Gets Accepted

Maintainer discretion applies. Not all contributions will be merged, particularly those that conflict with the project's direction or require significant ongoing maintenance burden.

## Questions

If you are unsure whether a contribution is appropriate, open an issue and ask before investing significant time.
